# Editorial content rework — local runbook

## Dry-run

```sh
cd backend
php artisan pts:content-rework-apply --baseline=/home/admin01/orca/artifacts/PTS-CONTENT-REWORK-BASELINE-20261112.json --proposal=/absolute/path/approved-knowledge.json --proposal=/absolute/path/approved-corporate.json --proposal=/absolute/path/approved-solutions.json
```

The command is fail-closed if any required staged Markdown, approved summary, or baseline hash is missing/drifted. It never searches generic untrusted directories.

Each article must carry an explicit `approved`, `qa_approved`, or `solid` status in its frontmatter/proposal; `hold`, `merge_candidate`, `Không xuất bản độc lập`, internal QA headings, and `Nguồn tham khảo cần gắn khi xuất bản` are rejected. Proposal entries may use either `post_id` or `id` (including `ARTICLE-100`/`SOLUTION-133`) and may have a `keywords` array; the engine does not treat keywords as an article identifier. Every entry must also explicitly verify non-empty sources and images before it can pass the gate.

## Apply and rollback

Only local/testing may apply. Because most targets are visible, the operator must explicitly add `--apply --allow-visible`. The command writes a full post/SEO JSON backup to Laravel's private `local` disk before the transaction. It does not provide an automatic rollback command: restore must be reviewed and executed by an operator from the reported backup, inside a separate local transaction, after checking the current rows have not changed; do not claim rollback is complete until row hashes are verified.

```sh
php artisan pts:content-rework-apply --baseline=/home/admin01/orca/artifacts/PTS-CONTENT-REWORK-BASELINE-20261112.json --proposal=/absolute/path/approved-knowledge.json --proposal=/absolute/path/approved-corporate.json --proposal=/absolute/path/approved-solutions.json --apply --allow-visible
```

## Data migration plan

No schema migration is required. Stage and QA Markdown/proposals, take the private backup generated by the command, run dry-run, then apply one all-or-nothing batch in local/testing. Verify body/summary/nav title, visibility, slug, dates, category, cover, source links, images, product links and second-run NOOP before any separately approved deployment process.
